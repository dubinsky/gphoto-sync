= Google Photo Synchronization

Manage the local photo archive and publish its albums to Google Photos.

== Archive layout

Originals are laid out as `YYYY/MM/DD`.
One album file describes one album.
A picture may be in several albums.
Date grain and an optional name are not types.
The file sits in the start folder, next to the pictures or the day folders.
The title is not the path.
There is no year album.
A `.toml` in a year directory is not an album.
A digit-leading `.toml` in a day folder is a picture sidecar.
A curated album is `originals/<Name>.toml`.
The name is not a 4-digit year, not `album`, and not `to-…`.
`rootPath` in the config file is the archive.
On this machine that is `Pictures/originals`.
The inbox is the child `.upload`.
Publish uploads JPEG and video.
RAW stays local.
The old sibling `Upload` is gone.
`lsd` skips a child whose name starts with `.` at year, month, and day, then puts `.upload` back on the archive root.
`AGENTS.md` may sit in the archive root.
Any other non-toml file next to child directories is stray.
`.gphoto-sync/` is the agent's workspace.
This program does not read it.
There is no config key for it.

The title uses `/` on both sides of a range.
`-` means only "through".

|===
| Title | Meaning
| `YYYY/MM` | that month
| `YYYY/MM-MM` | start month through a later month of the same year
| `YYYY/MM-YYYY/MM` | start month through a later year-month
| `YYYY/MM/DD` | that day
| `YYYY/MM/DD-DD` | start day through a later day of that month
| `YYYY/MM/DD-MM/DD` | start day through a later month and day of that year
| `YYYY/MM/DD-YYYY/MM/DD` | start day through a later civil date
| any of those plus `/Name` | the same span, with a name
|===

An equal day canonicalizes.
`2010/07/19-19` is the title `2010/07/19`.
An equal month is rejected.
`2010/07-2010/07` is not an album.
A name is not exactly two digits, does not start with a digit, does not start with `to-`, and is not `album`.

The end date is only in the filename, with the prefix `to-` and hyphens where the title uses slashes.
There is no `to` key.
An unnamed album of exactly that folder is `album.toml`.
A named album of exactly that folder is `Name.toml`.
A span is `to-<end>.toml` or `to-<end> Name.toml`.
In a day folder the end is `DD`, `MM-DD`, or `YYYY-MM-DD`.
In a month folder the end is `MM` or `YYYY-MM`.
`to-02` is day 02 in a day folder and month 02 in a month folder.
`2010/07/19/to-19.toml` is an error.

|===
| File under `originals/` | Title
| `2010/07/album.toml` | `2010/07`
| `2016/07/Camp Menucha Rochel.toml` | `2016/07/Camp Menucha Rochel`
| `2005/04/Toronto.toml` | `2005/04/Toronto`
| `2011/06/12/album.toml` | `2011/06/12`
| `2011/06/12/Chupa Sonya.toml` | `2011/06/12/Chupa Sonya`
| `2010/07/04/to-18 Cape Cod.toml` | `2010/07/04-18/Cape Cod`
| `2010/07/19/to-08-23.toml` | `2010/07/19-08/23`
| `2010/08/05/to-17 Seattle.toml` | `2010/08/05-17/Seattle`
| `2010/02/28/to-03-07 Purim Seuda.toml` | `2010/02/28-03/07/Purim Seuda`
| `2009/07/03/to-09-12.toml` | `2009/07/03-09/12`
| `2010/07/to-2011-02.toml` | `2010/07-2011/02`
| `Best.toml` | `Best`
|===

Membership is the `include` list.
A missing `include` is an empty album.
`include` is required for a non-empty album.
An entry is `all`, a date expression, a date plus one stem, or a date plus `stem..stem`, and it may end with `except`
and stems.
There is no album-level `exclude`.
`all` means every picture whose folder day is in the title span, and it is illegal when the album has no span.
A stem range is inclusive string order.
Both ends have the same width.
An except stem must be one the positive pattern can match.
Quote a stem only when a bare token would be wrong: it contains a space, `"`, `\`, or `..`, or it is the word `except`.
The tools write the bare form otherwise.
The parser accepts unnecessary quotes.
Album membership uses the folder day.
It does not use a filename clock.

Hand-written keys, in order, are `external`, `google-title`, `owner`, `google-album-id`, `published-title`, and
`include`.
Do not pass that file through jtoml.
jtoml rewrites sort keys and drops comments.
`storeGoogle` and a sync rewrite may still use jtoml.
`google-title`, when set, is the Google Photos title, stored exactly, including spaces.
Empty means that title is the path title.
`owner`, when set, is the display name of someone else who owns the album.
That file is `external`, has no `google-album-id`, and is not renamed.
`published-title` is the title this client last wrote, not that override.

== Clock

Filename clocks and JPEG `DateTimeOriginal` are civil times stored as UTC instants.
A video timestamp override writes that same string as QuickTime `CreateDate`.
File mtime still goes through the zoned conversion marked TODO on `Dates.FromFile`.
This program does not change that conversion.
One trailing `_1` is ignored.
Full, compact, and short names store the civil clock as a UTC instant.
A 13-digit name is an epoch instant.
`ls` may use the sidecar `date` for a short name.
Album membership uses the folder day, not this clock.
`ls` and `repair` share one assessment.
The assessed instant is the sidecar timestamp when one is present, otherwise the earliest of the file metadata times and
the filename clock.
File times more than 60 minutes apart are reported as varying.
January 1 of 1980 and January 1 of 2000 stay in their folders.
`repair --timestamps` sets file mtimes from that instant.
`repair --days` moves the picture to the calendar day of that instant, read as a UTC civil date.

== Commands

`photo lsd <directory>` lists directories.
`--long` lists nested directories.

`photo ls <path>` lists pictures and prints name, timestamp, and day mismatches.
It does not rename, generate, set mtimes, rewrite albums, or move files.

`photo repair <path>` writes repairs.
At least one of `--names`, `--raw`, `--timestamps`, and `--days` is required.
`--names` renames one leading `MVIMG_`, `PXL_`, `IMG_`, `VID_`, or `MVI_` prefix, refuses a non-digit stem, and
lowercases a known extension.
It rewrites `JPG` to `jpg`, `CR2` to `cr2`, and `Mp4` to `mp4`.
It does not rename `JPEG`.
`--raw` makes a JPEG from RAW with dcraw when no normal image exists and `bad-raw` is not set.
`--timestamps` sets file mtimes from the assessed instant.
`--days` moves a picture into the assessed day folder, rewriting curated include paths before any file moves.
The steps run in that order, and each later step sees the files written by the earlier ones.
`--dry-run` prints those actions and writes nothing.

`photo set-metadata <property> <picture>` sets one sidecar property.
The picture argument is the stem, without `.jpg`.

`photo albums [path]` lists album claims.
Each picture line ends with `albums=` and every claiming title, in Scala string order, with no spaces after commas.
`2009/03/10/2412 albums=2009/03/10/Party,Best` is a picture in both albums.
An empty claim and an excluded-only claim both print `albums=-`.

`photo publish [path]` uploads JPEG and video into albums and files existing media ids.
A year or the archive root requires `--recursive`.
`--dry-run` prints the local plan and does not call Google.
A picture is added to every non-external album that lists it.
A picture in any external album is not uploaded.
An unclaimed picture is left out of the summary.
A picture excluded from every album that matches it counts as skipped-excluded and is not uploaded.

`photo sync [path]` reads Google and turns removals into local except lists.
A year or the archive root requires `--recursive`.
`--dry-run` reads Google, prints except and remove lines, and does not write.
An except line is `except`, the album title, and the stem in quotes.
A remove line is `remove`, the album title, and the stem in quotes.

`photo login`, `photo status`, and `photo logout` manage the Google Photos token.

== OAuth and config

The Desktop client JSON is `~/.config/org.podval.tools.photo.client.json`.
The token is `~/.config/org.podval.tools.photo.token.json`.
The config file is `~/.config/org.podval.tools.photo.toml`.
It has `rootPath` and `zoneId`.
`rootPath` is the archive, relative to the home directory.
`byYearDirectoryName` or `uploadDirectoryName` is an error.
`rootPath` must be the archive.

== Google Photos API

The Library API, since 31 March 2025, can create albums and upload, and can list or edit only content this OAuth client
created.
It cannot list or rename albums I made by hand, and it cannot delete media.

== History

I started dabbling in this area around year 2000, when our daughter was born and I got my first digital camera :)

=== Metadata Extraction

My take on extracting metadata from image files is in the (now archived)
https://github.com/dubinsky/podval-imageio[podval-imageio] repository.

There, between 2003 and 2009, I worked on:

- extracting image metadata from the image file
- extracting thumbnails from the raw image file
- demosaicing raw images

There were some good ideas there:

- describing metadata structure in XML
- push and pull parsing of the metadata

I contributed small discoveries I made in 2002 about Canon RAW format (crw) to David Burren.

In the end I realized: it does not make sense to do this myself when there are groups of people who dedicate significant
time to developing and maintaining dedicated tools like `dcraw`, `metadata-extractor` and `ffmpeg` :)

=== Synchronization with the Cloud

My previous attempt at code to synchronize local photo archive with the cloud photo services is in the (now archived)
https://github.com/dubinsky/podval-photo-sync[podval-photo-sync] repository.

There, between 2009 and 2011, I worked on:

- synchronizing with Zenfolio (which I no longer use)
- synchronizing with Picasa and Google+ (which no longer exist)
- expose locally recorded timestamp and image orientation to the cloud service

There were some good ideas there:

- group files belonging to the same picture (raw, jpg, metadata)
- use family polymorphism to abstract over cloud photo services

In the end, while chasing ever-changing cloud, I neglected the management of the local photo archive - something that
this repository finally delivers.

This client publishes albums whose files I have written.
Historical albums are marked `external`.
Ones I own are renamed by hand.
Ones I do not own have `owner` and `google-title` and are not renamed.
Publish does not upload or rename an external album, and it does not call `updateAlbumTitle` for an album with `owner`.
Cron is out of scope.
